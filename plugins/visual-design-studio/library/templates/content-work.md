# Content extension for the design work record

Version-Timestamp: 2026-09-08 15:37:53 AST

Insert selected fields under Decisions and work in [design work](design-work.md). Reuse existing scope, inputs, checks and handoff sections. This is a manual authoring contract, not a new validator or required standalone file.

## Brief and foundations

Record audience/need IDs and evidence status; objective and next action; channel/page/state IDs; locale; authoritative voice/terminology sources and proposed exceptions; offer/product truth; baseline and allowed changes; selected guide and method rationale. Reference the existing UXD-13 inventory and UXD-22 messages where selected.

## Copy units

For each selected unit: stable ID/key, parent page/section/component/channel, purpose, trigger where applicable, exact candidate text, source/claim IDs, variables and allowed values, locale, relevant length/layout constraints with their source, CTA destination/behavior, approval/use status and owner. For static prose mark trigger/variables not applicable. Keep alternatives separate from the selected candidate.

## Evidence and review

Map claims to source/version, scope, freshness, permitted use and unresolved questions. Record actual fact, voice, read-aloud, accessibility, localization, layout/state and specialist reviews in the existing Checks and limits section. Distinguish not-run checks from passes. Mark unsupported claims for removal, evidence collection or explicitly limited exploration, never silent adoption.

## Next consumer and change propagation

Reference copy version/path and exact unit IDs in the stage packet. Name the receiving layout, CMS, component, production or editorial owner and held decisions. Changes to offer, claim evidence, voice, locale, action or state trigger must identify affected units, layouts and tests for reassessment. Maintain one canonical copy source and update consumers from it; do not silently edit divergent text in multiple apps.

## Conditional fields

Reference the audience disposition and rationale under the shared audience contract; selected full personas retain its complete-field requirement. For migration/restructure, map old URLs/sections and existing content IDs to retained, revised or proposed removal destinations; pass this to the implementation owner without executing redirects/deletions. Record the actual author/reviewer, expertise basis and any project/channel disclosure requirement when applicable. Do not invent authorship or assume a universal AI disclosure rule.
