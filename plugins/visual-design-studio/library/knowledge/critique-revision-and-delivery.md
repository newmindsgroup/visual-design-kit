# Turn critique into a bounded repair

Version-Timestamp: 2026-09-27 14:20:29 AST

Use when reviewing a candidate, acting on feedback, or preparing a delivery. Inputs: brief, criterion basis, baseline, exact candidate, allowed delta, target conditions and required output formats. This is original authored guidance; the miniature is fictional and records no executed acceptance checks.

## Make the decision

1. Freeze what is being judged. Name the artifact/version, audience/use, content, target size and invariants. A thumbnail, source file and exported PDF can reveal different failures; choose evidence appropriate to the claim. If the actual artifact is unavailable, label the result a specification review.
2. Classify the finding before scoring it. Is it an incorrect fact, unmet requirement, craft defect, production problem or preference? Point to the affected region/frame and explain the consequence. “The offer condition is missing” is different from “I prefer a quieter background.” Do not average a factual or access failure into a favorable aesthetic score.
3. Diagnose the smallest plausible cause. If a headline loses priority, inspect size, weight, surrounding contrast and competing image mass. If it clips, inspect its container and font behavior. Changing all of them at once may improve the image, but cannot establish which change fixed the problem.
4. Propose a bounded repair: intended change, preserved properties, expected visible result and check. Prefer the least disruptive correction that meets the requirement. A request to enlarge a logo does not authorize new typography or a different background. If the requested change would break another requirement, show the conflict and a concrete alternative within scope.
5. Compare before and after under identical conditions. Recheck the changed feature and areas likely to be affected. A width change may alter wrapping; a type-weight change may affect contrast criteria; a new asset may affect crop, rights and exports. Preserve historical failures and mark stale dependent evidence rather than overwriting it with an optimistic summary.
6. Stop at the accepted scope, then reconcile the delivery. Use the current native master, export from that version, reopen actual outputs and confirm the package contents and instructions. Keep source integrity, visual quality, rights, native editability, target behavior and approval as separate claims. Delivery preparation does not itself send or publish anything.

## Worked miniature

A fictional event flyer uses the approved title “Mend It Saturday.” Feedback requests “make the title easier to read.” The observed issue in the candidate is a busy photograph behind the title, while title size and line fit are already adequate. The bounded repair moves the title onto the existing plain surface, preserving copy, typeface, image identity, colors and event details.

The comparison should inspect title legibility, revised spacing, photograph crop and every required detail at the same output size. If this repair meets the criterion, there is no reason to explore new fonts. The delivered PDF must still be generated from the repaired source and reopened. A screenshot of the improvement would not establish that the PDF contains it.

## Failure and repair

If feedback is “make it premium,” translate it into a reviewable criterion before generating variants: for example, reduce inconsistent spacing or improve material fidelity, if that fits the brief. Do not treat a genre as a quality level. If revisions improve one region but change approved details elsewhere, restore the invariants and narrow the operation. If checks pass on an old export, regenerate and test the current one; updating its filename or manifest alone cannot fix stale content.

## Handoff and limits

Use `delivery` with [design work](../templates/design-work.md): Decisions and work for rationale, Change boundary for invariants, Criterion basis for methods, Checks and limits for actual evidence, and Handoff for next action. Reuse [calibrated critique](../draft-skills/design-foundations/references/critique-calibration.md), [stage execution](../templates/stage-execution.md) and [delivery preflight](../DELIVERY-PREFLIGHT.md).

Check that each required finding has a disposition and owner, repairs preserve scope, results bind to current versions, and actual outputs match requested formats. A model's preference does not establish user preference; a manifest pass does not establish correct pixels or editability; a reviewed candidate does not establish permission to release.
