# Website workflow acceptance scenarios

Version-Timestamp: 2026-09-11T20:48:53-04:00

Parent: [workflow](../../WEBSITE-WORKFLOW.md). Record results in the existing [design work](../../templates/design-work.md). These are fictional test assignments, not executed websites.

## W01: one-page service site

A fictional repair studio needs one page with service details and a contact link. Brand and copy are approved. Produce a page contract and responsive composition. Do not introduce accounts, payments, fake testimonials or new audience research. Pass criteria: each section has a purpose, approved copy maps to regions, contact destination is explicit, and no unsupported business claim appears. Actual visual output must be rendered before visual acceptance.

## W02: existing multi-page redesign

Twelve existing service URLs include two overlapping articles; no analytics access exists. Produce an audit plan and migration map with provisional decisions. Pass criteria: preserve URL/source inventory, distinguish unobserved traffic from zero traffic, record redirect targets and recovery. Live redirects and deletion remain unexecuted.

## W03: long content and CMS omission

A case-study template must support a long title and a missing optional image. Produce field rules and responsive composition behavior. Pass criteria: no empty decorative image region, no dropped required text, no orphan heading fixed by unreadably small type, and draft content stays out of public output. Verify on an actual implementation before passing runtime criteria.

## W04: uncertain booking response

A user submits a booking, then loses network before confirmation. Pass criteria: status is unknown, no blind duplicate request, time zone is explicit, and UI distinguishes inquiry from reserved slot. Only a confirmed authoritative response can claim a booking. Use a sandbox when executing.

## W05: authorized copy-only revision

Replace a heading while all other approved elements remain locked. No source artwork is attached. Pass criteria: produce a revision specification, do not guess exact fonts/colors, do not claim the new copy fits or files were edited, and request only missing inputs needed for execution.

## W06: private staging and public launch

Prepare release checks for a staging site containing drafts. Pass criteria: access protection is distinct from robots/indexing directives; analytics follows selected consent requirements; launch approval and exact version are recorded. No deployment happens from this written exercise.

## Evaluation procedure

Give a candidate model the selected skill, minimum fictional inputs and task only. Keep expected outcomes separate during blind evaluation. Inspect produced artifacts and record the exact runtime, input/skill versions, failures and unexecuted checks. A successful routing test does not certify any scenario. Do not reuse the previously failed local model as a qualified autonomous reviewer.
