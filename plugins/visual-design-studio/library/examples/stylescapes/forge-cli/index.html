§7 imagery

No stock, no orbs, no robots. Pictures are schematics of the real system, drawn with the same hairlines and labels as the code annotations.

Diagrams use a 16px dot grid, 1px boxes, mono labels and dimension lines for real measurements (latency, size). One path, the one being explained, is amber.

Icons are 1.5px square-cap strokes on a 16px grid, drawn like schematic symbols. No rockets, lightning bolts, sparkles or brains.

§10 rationale

Rationale

Why a shop drawing, and not a light show.

Why it fits

Expert developers buy what they can inspect. The Magician here is the kind who explains the trick: the hero is a real agent definition, the real deploy output and numbered notes tying the two together, like a technical drawing. Dark, because that is where developers read code, but warm and quiet, with a light theme built in.

What it risks

  • Density. Non-engineering buyers may bounce; give them a separate “for teams” page.
  • Every number in the hero becomes a promise; benchmarks need a public method and a date.
  • Annotations must stay true as the SDK changes; generate the hero code from a tested example.

The expected alternative

Black page, purple-to-blue radial glow, centered “Build AI agents 10x faster”, a terminal that types npm install forever, glass cards with fake metrics. Recognizable, interchangeable and slightly untrustworthy to the people who matter most.
