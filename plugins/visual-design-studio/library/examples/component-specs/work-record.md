## Criterion basis and reproducible methods

These methods are instructions for a future implementation, **not executed component tests**. Every criterion below has result pending and no artifact evidence. Expected behavior/state definitions belong to the linked item; the method is authored only here. Project owner has no exception authority over a claimed normative requirement: any scoped exception must match that source and be recorded, or the claim fails.

Applicability is owned by each item’s selection table and recorded through the [selection guide](selection-guide.md). The fourteen criterion IDs remain stable; selected branches are recorded by their names below. Omitted branches require a trigger-based reason and are not passed tests. A held required branch blocks the affected behavior. SH-01/SH-02 remain required for selected content/controls, subject only to source-defined applicability.

Before executing, record implementation revision, approved token file, browser/OS/assistive-technology versions, input device, locale/direction and fixture. Only for selected async/domain/remote behavior, use a controlled local adapter to provide success/failure/late responses without contacting real services. Start with a fresh fixture per case. Repeat relevant cases across the project's declared support matrix; a single passing environment does not cover the others. None is selected here.

The selected web baseline is WCAG 2.2 A/AA criteria relevant to these examples, not a whole-product conformance assessment. Source WCAG is the Recommendation dated 12 December 2024. APG/tutorial guidance is informative; HTML semantics follow its checked living standard. Example-specific requirements are original teaching choices, not vendor rules. Native conformance targets require separate platform and applicable-standard scoping.
