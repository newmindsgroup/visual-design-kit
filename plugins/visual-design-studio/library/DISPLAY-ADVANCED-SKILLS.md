## Sequence

Discovery and existing brand evidence precede content architecture. Touch projects then select interaction patterns, product education, configurators or forms as needed. Define offline, session and action behavior before implementation. Evaluate task usability and actual recovery. Passive content selects attention, assortment, offers and formats before motion, playlists and finishing. Approval records bind the final versions; executable tests and evaluation examples supply evidence.

Reuse existing accepted inputs. Camera, payment, identification and sensor integrations remain conditional project requirements, not default capabilities or assumed hardware. No fixture design is included.

## Expanded skills

- [Search and comparison content models](draft-skills/design-touch-product-discovery/SKILL.md): Define authoritative product attributes, units, synonyms and missing-value semantics. Specify filter combinations, sorting and comparable attributes. Missing information is not a negative product feature. Test products with unequal data coverage.
- [Shared-device session management](draft-skills/design-touch-states-copy/SKILL.md): Use one coherent proposed inactivity schedule across states, with warning and extension before reset. Preserve active choices on extension. Clear all prior-shopper UI and personal data on reset. Operational reconciliation must remain separate from a fresh shopper session. Never invent backend or hardware capabilities.

## Status and limitations

These are authored project-local skills. The executable-tests skill instructs creation and execution against a selected implementation; this addition does not itself create or run a touchscreen application test suite. Production examples must be rendered and inspected before aesthetic acceptance. Prior local-model failures remain recorded in evaluation (source-repository evidence, not bundled or inherited). Independent Claude review remains pending authentication; no failed review retry or release was performed.

Structural and vault checks are recorded in screen checks (source-repository evidence, not bundled or inherited). Every catalog entry has a linked Markdown skill in the same repository-backed vault. No duplicated Obsidian-only source is created.
