Use this mode of [design evidence research](draft-skills/design-evidence-research/SKILL.md) when supplied videos should inform this project's skills, reference library or workflows. This is an original manual procedure, not an installed crawler, scheduled automation or separate design runtime. Create or reuse the adopting project's source register using the fields below. No populated authoring-project catalog is included.

## Source register fields

Use stable IDs and explicit unknowns. Record one video entry with supplied URL, canonical video ID/URL, title, creator, publication date, retrieval date, duration, description location/hash, caption language/source/location/hash, actual coverage/gaps and owner. Record each outbound or on-screen resource with parent video ID, original URL or timecode, redirect/final locator, retrieval result, inspection level, rights/use status and next action. Findings reference those IDs with claim versus verified evidence, destination owner, adopted/rejected/pending disposition and rationale. Keep raw content in the authorized private source store; this field list is a manual contract, not a new JSON schema.

## Capture and attribute

Resolve the authoritative project before writing. Normalize a YouTube URL to its video ID while retaining the supplied URL in the batch record. Reuse existing verified transcripts and files by path/hash; keep every source-to-resource relationship even when bytes or destinations repeat. Store full descriptions, captions, retrieved third-party text and downloaded resources outside reusable Git history in the approved private library. Repository records contain original synthesis, metadata and source pointers.

For every video record title, creator, publication/retrieval date, duration, description, exact outbound URLs, caption language/source and actual coverage. An early transcript-export failure can be a page-loading failure: inspect the loaded page and make one bounded retry before recording captions as unavailable. Preserve raw exports. Check start/end coverage, unexpected gaps and timestamp ordering; captions reaching the end are not proof of flawless speech recognition. Segment timestamps are not word alignment. Description chapters can disagree with playback and must not silently replace transcript locators.

Extract distinct methods, steps, tools, assets, technical claims, offered downloads and spoken/on-screen resources. Record pinned creator links and relevant cards when accessible. Distinguish a mentioned site, a followed URL, a readable landing page, an inspected resource file and a tested tool. Sample the frames needed to resolve visual-only details; state the times and remaining visual coverage. Do not describe selected frames as a full viewing.

## Follow resources to the usable material

Preserve each original link, redirect destination, retrieval result and inspection level. Follow creator resource posts, linked indexes and the actual files needed for the method. Inspect a page's substance before promoting it. HTTP 200 can contain only a login or application shell. A community landing page is not access to its posts, attachments or classroom. Record the exact gated destination and what would resolve access; continue independent public-source work.

A provided resource index is a finite collection: catalog its entries and reuse existing canonical records. Site-wide crawling is not implied. Keep category changes and redirects visible; never silently replace a dead link with a different resource. Revisit blocked or outdated destinations when a concrete task needs them.

## Decide where each finding belongs

| Finding | Destination |
| --- | --- |
| A useful method already covered | Link supporting evidence to the existing skill or contract; add no duplicate rule |
| A useful missing step within a capability | Add one concise conditional section or linked reference to that capability |
| A materially separate repeatable capability | Consider a new skill only after existing contracts and installed skills fail to cover it |
| A style, thumbnail, font specimen or reference site | Catalog as inspiration; preserve source and permitted-use limits |
| Software, plugin, connector or executable skill | Inspect exact source/version, license, access/data flows and dependencies before any proposed execution |
| An unsupported claim, gated file or missing prerequisite | Keep a named hold and next action; never invent the inaccessible method |
| An affiliate, social profile or unrelated offer | Catalog its attribution and exclusion rationale; do not make it a dependency |

Use primary documentation for selected technical facts. Creator statements about revenue, rankings, prices, model superiority or conversion remain claims unless the relevant evidence is obtained. Sales claims and asset rights are separate from visual quality. Retrieval does not establish runtime compatibility, account entitlement or permission to redistribute source files.

Use existing voice and content checks before considering a new writing tool. A pattern score is not factual proof, conversion evidence or human-authorship detection. Keep model choice and external calls under the existing routing and authorization rules.

## Integrate and close

Keep one canonical home for each method. Link the research register from the owning skill and preserve the approved project process. Record source IDs/timecodes, the exact delta, rejection reasons and actual checks. Use [reference selection](REFERENCE-SELECTION.md), [system adoption](SYSTEM-ADOPTION.md), [production](SOFTWARE-PRODUCTION.md) and [delivery](DELIVERY-PREFLIGHT.md) rather than recreating their contracts.

For an iterative design review, freeze the brief, baseline and criteria, render the candidate, identify concrete discrepancies, revise the justified delta and recheck. Use a bounded pass/time/cost budget; stop on acceptance, a blocker or repeated lack of progress. A new critic agent for every pass is optional, not a requirement. A reference comparison proposes changes; it cannot override locked identity tokens. Preserve any remaining failures in the handoff.

When a comparison needs more structure, separate three questions: does the result meet the brief, does it respect the approved system, and does its rendered presentation meet the selected reference criteria? Use pass, fail or unassessed with supporting evidence and the largest actionable gap for each. Do not require three model calls. Deterministic checks can establish mechanical facts; independent visual judgment needs the actual rendered evidence. A missing render makes visual judgment unassessed, not a pass. Keep source/code review available for behavior and security, alongside visual review.

Prepare a short list of observable reference mechanisms before revision, such as a specific type relationship or transition behavior. Record which mechanisms are observations and which are approved adaptations; an arbitrary numerical threshold is not a universal quality rule. Give an independent reviewer the task, constraints, comparison and actual result without persuasive builder commentary. Suppress author labels only where doing so preserves the meaning and rights of the evidence. When separately improved pieces are recombined, inspect the whole result for consistency and regressions. Maintain criteria, evidence, gaps and iteration history in the existing work record instead of creating a dashboard by default.

Derivation belongs to the source version pinned in the package manifest; original third-party material and private research records are not bundled.

Update project continuity with what is captured, inspected, integrated and still pending. Keep extraction completion separate from download access, method authoring, integration testing and production readiness. Do not mark the entire batch complete while promised gated material or required verification is outstanding.
