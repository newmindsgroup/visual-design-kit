## Order

Choose delivery format from actual requirements. Prepare approved content and sources. Select native or HTML production, batch variants where useful, then check fidelity, finishing and performance. Verify the complete approved package before CMS activation. Test target playback and restoration. Add audio or event behavior only when specified.

## Expanded owners

- [Delivery format selection](draft-skills/design-display-production/SKILL.md): Compare still, rendered video, HTML and interactive application against message, update frequency, offline needs, target player support and editable-source requirements. Prefer the simplest format that meets the brief. Record why richer runtime is needed; do not default every campaign to an app.
- [Campaign-wide consistency](draft-skills/design-screen-acceptance-records/SKILL.md): Compare every variant against one approved source matrix: logo, product, copy, palette, offer, language and version. Identify intentionally different values. A matching file hash proves byte identity, not brand accuracy or approval. Use product-fidelity review for actual artwork.

## Working example and limits

[Screen production example](examples/screen-production/README.md) includes original editable SVG illustrations for three screen formats, a repeatable renderer, exact export hashes and a local HTML sequence. It exercises static campaign construction, package verification and basic player state. It does not render video, integrate with a CMS, create a native animation project or validate a physical player. Those methods require project-specific execution evidence.

Prior failed local-model instruction evaluations remain unresolved. This deterministic example does not reverse those outcomes. No publication, native-app certification or universal performance budget is implied.
