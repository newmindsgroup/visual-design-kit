# Design craft and decision ownership

Original client-agnostic methods, not a universal aesthetic or a promise of exceptional output. Standards establish measurable requirements; design principles guide judgment; vendor systems illustrate choices; trends and psychological associations need context. Research provenance belongs to the source version pinned in the package manifest; optional research evidence is not bundled or promoted into current project validation.

## Select only the needed skills

- [Foundations](draft-skills/design-foundations/SKILL.md): composition, visual direction and craft critique.
- [Typography](draft-skills/design-typography/SKILL.md): selection, pairing, typesetting, font delivery and verification.
- [Color](draft-skills/design-color-system/SKILL.md): palette exploration, semantic roles, combinations and output behavior.
- [Motion](draft-skills/design-motion-effects/SKILL.md): purposeful interaction, scroll and expressive effect specifications.

Read only the selected references. Existing approved decisions may satisfy prerequisites. An exact revision does not trigger a redesign. Catalog dependencies load instructions; they do not force fresh research or a full persona for each choice. Audience selection follows [the capability contracts](CAPABILITY-CONTRACTS.md). No fixed cross-client font pair, palette, component silhouette or motion vocabulary is baked into these skills.

## One owner for each fact

The existing project work record owns scope, audience evidence, approval, baseline, allowed changes and holds. Research owns source observations. Reference-direction owns the direction decision. Identity owns the authoritative approved brand selection, including chosen typefaces and palette. Typography/color propose candidates for that owner and specify approved implementation details; they do not approve their own brand replacements. Typography owns font files/features and type-role geometry. Color owns semantic color mappings and the contrast-pair results, referencing typography role IDs and rendered sizes. Motion owns triggers, timing, transition states and fallback behavior. Production owns editable masters/export settings. Delivery owns the manifest and acceptance evidence.

The new selection sheets are attached records referenced from design-work.md by ID/path/version, not replacement briefs or duplicate token stores. Project tokens remain the actual value source. Color and type can be explored together, but neither has a catalog dependency on the other. A changed type size, color, background or font invalidates the affected contrast/render result until rechecked. A reviewer proposes a change to its owner; it does not silently rewrite approved values. Foundational guidance can be read during critique without recursively invoking new research.

## Craft review: make generic output observable

For a selected candidate, record the artifact/version, inspected viewport or print/display size, evidence capture, issue, consequence, proposed correction and remaining test. Evaluate:

1. Specificity: can each major visual choice be explained from this audience, content and brand? A name-swap thought experiment can reveal a generic structure, but is a heuristic, not proof of originality.
2. Concept: does imagery/layout tell this story rather than merely fill space? Compare genuinely different directions using the same core content when direction is open. An already approved direction needs careful execution, not artificial alternatives.
3. Hierarchy: is there a clear entry point and useful rhythm? Repeated cards, badges, centered headings, gradients or oversized type require a purpose when they dominate. None is banned solely for popularity.
4. Typography: distinctive where useful, comfortable where reading matters; accurate glyphs, good spacing, no fake weights or accidental fallback.
5. Color: roles remain clear across states and contexts; combinations, not isolated swatches, meet the selected accessibility target.
6. Composition and assets: coherent grid, optical alignment, meaningful whitespace, crop/lighting/icon consistency, truthful product representation and no unexplained decorative clutter.
7. Motion: explains state or supports an intentional experience without delaying tasks, hiding content or interfering with scrolling.
8. Completeness: realistic long/short/error/localized content, small screens, accessible alternatives, actual exports and native editability have been considered.

Use pass, revise or not tested per criterion with evidence. Do not average a failed legibility or access requirement into a favorable aesthetic score. A model's opinion or a screenshot of somebody else's site is not validation of the candidate. For visual work, inspect actual desktop/mobile or appropriate target renders and interactions. Mark unaudited field conditions honestly. No automated detector establishes the absence of AI slop, originality or commercial success.

A productive revision changes the smallest set of decisions that fixes the identified problem. Preserve accepted content and brand invariants. Stop when agreed criteria are met; unresolved taste choices go to the named design owner rather than an endless variant loop.

## Dependency rationale

Foundations depends on reference-direction (which includes research) and handoff to reuse source/direction and baseline contracts. Typography and color each depend on foundations, with no mutual dependency; composition reconciles their linked choices. Motion additionally loads production because representation/tool/export selection is part of its operating procedure. Typography supplies font specifications to the existing production owner; it does not execute an independent production stage. Identity/UI link these specializations as optional procedures, so ordinary accepted work does not acquire mandatory new catalog branches. Instruction dependency loading is not a requirement to redo prior stages.
