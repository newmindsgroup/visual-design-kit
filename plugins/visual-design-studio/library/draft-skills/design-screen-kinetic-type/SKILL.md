# Kinetic typography

Version-Timestamp: 2026-09-11T19:51:13-04:00

## Objective and inputs

Produce kinetic typography within the user's screen-content scope. Read the [screen workflow](../../SCREEN-CONTENT-SKILLS.md) and reuse approved upstream files, brief, source versions and constraints. The catalog dependency `screen-storyboard` identifies required information, not a mandatory rerun. Missing inputs are explicit assumptions or scoped holds.

## Method

Set readable static typography before animation. Animate semantic phrases rather than arbitrary character effects unless the direction calls for them. Hold complete messages; avoid moving the only readable text continuously. Preserve final line balance across variants.

## Output

Editable text animation with font dependencies and hold timings. Carry source version, candidate status, editable file location, dependencies, limitations and next owner in the [handoff](../design-stage-handoff/SKILL.md). Choose an available tool suited to the artifact; a skill does not establish authentication, paid allowance or native editing capability.

## Acceptance

Inspect full message visibility, line breaks, fallback fonts, long copy and silent comprehension. Record actual evidence and failures. Never label an unexecuted check passed. Maintain the approved baseline until the candidate is accepted.
