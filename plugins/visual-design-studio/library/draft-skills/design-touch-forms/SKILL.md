# Touchscreen forms and input

Version-Timestamp: 2026-09-11T20:08:06-04:00

## Inputs and scope

Read the [advanced workflow](../../DISPLAY-ADVANCED-SKILLS.md). Reuse accepted `touchscreen-design` inputs, source versions, objective and constraints. Dependencies express information needs, not mandatory repeated work. Scope is screen content and interaction, not fixture design. Unknown facts remain unknown.

## Method

Minimize fields and select appropriate keyboards. Keep labels and error messages visible when keyboard opens. Preserve valid input during correction; mask sensitive values and define clearing rules. Support relevant input alternatives without assuming installed peripherals.

## Deliverable and handoff

Field contract, keyboard/layout states and validation copy. Include exact files actually created, candidate status, assumptions, failed checks and next owner through the [handoff](../design-stage-handoff/SKILL.md). Proposed paths are not produced files. No installed tool, publication authority or provider access is implied by this skill.

## Acceptance

Test long values, keyboard occlusion, correction, cancellation and reset without retaining personal data. Record observations separately from expected behavior. Missing runtime evidence remains pending; do not label plans or descriptions tested. Keep prior approved versions recoverable.
