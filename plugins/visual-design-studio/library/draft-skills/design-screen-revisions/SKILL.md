# Precise content revisions

Version-Timestamp: 2026-09-12T11:35:16-04:00

## Objective and inputs

Produce precise content revisions within the user's screen-content scope. Read the [screen workflow](../../SCREEN-CONTENT-SKILLS.md) and reuse approved upstream files, brief, source versions and constraints. The catalog dependency `handoff` identifies required information, not a mandatory rerun. Missing inputs are explicit assumptions or scoped holds.

## Method

Capture requested change, approved version and protected elements. Classify affected copy, assets, timeline and exports. Make the smallest sufficient edit on a new version; compare before/after and rerun affected checks. Preserve previous approved deliverables and explain unavoidable knock-on changes.

## Output

Change record, revised editable source and affected-export list. Carry source version, candidate status, editable file location, dependencies, limitations and next owner in the [handoff](../design-stage-handoff/SKILL.md). Choose an available tool suited to the artifact; a skill does not establish authentication, paid allowance or native editing capability.

## Acceptance

Verify untouched elements remain unchanged and approval is not silently inherited by the revised candidate. Record actual evidence and failures. Never label an unexecuted check passed. Maintain the approved baseline until the candidate is accepted.

## Missing-source and copy-fit safeguards

Version-Timestamp: 2026-09-11T19:55:10-04:00

Never infer a hex value from a color name, copy a source timestamp as the current time, invent font/position values, or claim a longer replacement fits before measurement. Treat layout impact as unknown until checked. Without artwork, produce a revision specification only; a placeholder is not evidence of faithful preservation. Reconstruction is possible through the reconstruction skill when suitable inputs exist, but is not an exact revision or inherently forbidden. Do not invent an extra approval requirement for already authorized reversible work. Distinguish proposed filenames from files actually created.

The comparison CLI treats lists and empty objects as whole values. It cannot verify an invariant such as frames.0.label inside a list. Declare the whole list invariant, use stable object keys where appropriate, or run a separate element-level check; never claim element preservation from the list-level result alone.
