# Identity asset delivery

Version-Timestamp: 2026-09-11T19:25:03-04:00

Status: authored project-local instruction. No installation or production acceptance implied.

## Inputs and routing

Use the [identity workflow](../../IDENTITY-WORKFLOW.md) and [identity handoff record](../../templates/identity-handoff.md). Reuse accepted inputs with version and scope; dependencies are information requirements, not mandatory reruns. Existing [identity](../design-identity-system/SKILL.md) coordinates selected stages.

## Method

Start from the approved variant matrix and target-use requirements. Select formats intentionally: editable native master, vector exchange and raster derivatives as needed. Do not deliver every extension by habit. Record RGB/print-specific color intent and use actual printer requirements for CMYK/spot workflows; automatic conversion does not establish a color match.

Check native editability, vector path integrity, text/outline intent, transparent backgrounds, artboard/viewBox bounds, dimensions, profiles and export consistency. Verify thumbnails and reopen representative files through the target route. Ensure no unintended raster image masquerades as a fully vector mark. Bind exports to source version and hash with the existing manifest rather than invent a second schema.

Use predictable variant/use/color filenames, license notices and a concise recipient guide. Do not redistribute font software or third-party source assets without applicable rights. Separate working files, approved masters and deprecated variants. Preserve previous release and record differences. Deployment, sharing and rights transfer require the appropriate actual authorization; a completed ZIP alone is not client acceptance.

## Output and acceptance

Checked asset package, source/export manifest, variant index, usage guide, rights dependencies and release limitations.

Carry file versions, approval scope and unresolved checks through [stage handoff](../design-stage-handoff/SKILL.md).
