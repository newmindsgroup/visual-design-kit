# Content specification and approval records

Version-Timestamp: 2026-09-11T20:08:06-04:00

## Inputs and scope

Read the [advanced workflow](../../DISPLAY-ADVANCED-SKILLS.md). Reuse accepted `handoff` inputs, source versions, objective and constraints. Dependencies express information needs, not mandatory repeated work. Scope is screen content and interaction, not fixture design. Unknown facts remain unknown.

## Method

Bind copy, assets, screen assignment, rights and acceptance to exact versions. Record who approved what scope and when. Changes invalidate affected approvals only. Keep superseded records, and distinguish candidate, approved and delivered.

## Deliverable and handoff

Version-bound content specification and approval matrix. Include exact files actually created, candidate status, assumptions, failed checks and next owner through the [handoff](../design-stage-handoff/SKILL.md). Proposed paths are not produced files. No installed tool, publication authority or provider access is implied by this skill.

## Acceptance

Trace any export to exact sources and approval; reject ambiguous or stale approval references. Record observations separately from expected behavior. Missing runtime evidence remains pending; do not label plans or descriptions tested. Keep prior approved versions recoverable.

## Campaign-wide consistency

Version-Timestamp: 2026-09-11T20:19:25-04:00

Compare every variant against one approved source matrix: logo, product, copy, palette, offer, language and version. Identify intentionally different values. A matching file hash proves byte identity, not brand accuracy or approval. Use product-fidelity review for actual artwork. See [production workflow](../../SCREEN-PRODUCTION-WORKFLOW.md).
