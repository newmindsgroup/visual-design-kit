# Landing pages and conversion paths

Version-Timestamp: 2026-09-12T11:35:16-04:00

## Inputs and scope

Read the [website workflow](../../WEBSITE-WORKFLOW.md). Reuse accepted `content` inputs and the relevant [website work sections](../../templates/website-work.md). Record intended outcome, audience evidence, exact source versions, platform constraints and allowed change. Dependencies express information needs, not a compulsory restart of approved work.

## Method

Map intent to an offer, credible evidence and a clear action. Choose page structure for the decision, not a fixed persuasion formula. Use authentic testimonials and sourced claims. Avoid manipulative controls and fabricated scarcity. Include alternatives for visitors not ready to act.

## Deliverable

Landing-page content/layout brief and conversion-path map. Attach to the existing design-work record with stable page/component/content IDs. Hand off actual file paths, candidate status, assumptions, unexecuted checks and next owner. Proposed filenames are not produced files. Missing tools hold dependent execution only.

## Acceptance

Trace promise to destination and confirmation; proposed improvements are hypotheses, not guaranteed conversion gains. Preserve prior approved work. A specification, sample or simulated interaction is not proof of production behavior. Use [acceptance scenarios](../../examples/website-workflow/README.md) and project-specific checks; no external changes or installation are implied.

Complete the [stage handoff](../design-stage-handoff/SKILL.md) with actual files, version, checks, unknowns and next owner.
