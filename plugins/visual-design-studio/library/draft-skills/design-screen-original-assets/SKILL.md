# Original supporting assets

Version-Timestamp: 2026-09-11T19:51:13-04:00

## Objective and inputs

Produce original supporting assets within the user's screen-content scope. Read the [screen workflow](../../SCREEN-CONTENT-SKILLS.md) and reuse approved upstream files, brief, source versions and constraints. The catalog dependency `display-art-direction` identifies required information, not a mandatory rerun. Missing inputs are explicit assumptions or scoped holds.

## Method

Translate the selected direction into a brief for backgrounds, illustrations, patterns and textures. Record intended empty zones for copy and products. Use available approved tools; generation requires scoped allowance. Keep generated supporting assets separate from factual packshots and mark synthetic imagery.

## Output

Editable supporting assets, generation provenance when applicable and reusable style rules. Carry source version, candidate status, editable file location, dependencies, limitations and next owner in the [handoff](../design-stage-handoff/SKILL.md). Choose an available tool suited to the artifact; a skill does not establish authentication, paid allowance or native editing capability.

## Acceptance

Check artifacts, repetition seams, brand fit and ownership; do not fabricate product facts. Record actual evidence and failures. Never label an unexecuted check passed. Maintain the approved baseline until the candidate is accepted.
