# Brand guidelines production

Version-Timestamp: 2026-09-11T19:25:03-04:00

Status: authored project-local instruction. No installation or production acceptance implied.

## Inputs and routing

Use the [identity workflow](../../IDENTITY-WORKFLOW.md) and [identity handoff record](../../templates/identity-handoff.md). Reuse accepted inputs with version and scope; dependencies are information requirements, not mandatory reruns. Existing [identity](../design-identity-system/SKILL.md) coordinates selected stages.

## Method

Gather authoritative decisions and asset versions. Include only applicable sections: strategy summary, naming/architecture, logos, type, color, imagery, illustration/characters, graphic elements, layout, verbal identity, motion and channel examples. Link canonical tokens and assets instead of creating conflicting copies.

Give rules with practical examples, exceptions, do/dont comparisons and reasons. Clearly separate approved, provisional and prohibited treatments. Establish source precedence and a contact/decision owner. For existing brands, preserve supplied guideline authority and identify extensions. Use client-specific values only in the separate client project, never this reusable library.

Provide a readable guide and concise AI handoff with stable rule/asset IDs, locks and allowed variations. Show full-color, monochrome and relevant application cases. Confirm links, version/date and file references. If producing PDF/web, inspect each actual rendering, navigation, accessible reading structure and matching content. An authored Markdown guide is not a verified PDF or deployed site.

## Output and acceptance

Guideline source, requested rendered editions, canonical rule/asset index, exceptions and handoff instructions.

Carry file versions, approval scope and unresolved checks through [stage handoff](../design-stage-handoff/SKILL.md).
