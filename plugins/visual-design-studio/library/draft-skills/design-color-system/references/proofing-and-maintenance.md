# Color proofing and palette maintenance

Version-Timestamp: 2026-09-11T19:32:14-04:00

Obtain the target device/print process, stock, profiles and approved color intent. Distinguish assigning a profile from converting color values. Preserve the source, embed the appropriate profile and record conversion/rendering intent. Soft-proof with the intended output profile and inspect gamut warnings; do not invent a spot-color equivalent from a hex code. Use physical proofs or measured display conditions where fidelity matters.

Record calibration/profile status, viewing illumination and proof limitations. Compare intended and observed output, then obtain an approved reproduction-specific variant if needed. A browser screenshot is not a contract proof. Do not claim perceptual match solely from RGB equality.

Maintain canonical tokens, semantic aliases, approved pair records and dependent artifact IDs. When changing colors, compare before/after records and rerun affected states/themes, images and typography combinations. The helper reports added/changed/removed pairs by signature; it does not automatically discover every consumer or authorize editing them.

Sources: [ICC profiles](https://www.color.org/profile/), [ICC display calibration](https://www.color.org/displaycalibration/) and [WCAG 2.2](https://www.w3.org/TR/WCAG22/). Verify project applicability and actual device support at execution.

Use the [craft laboratory](../../../CRAFT-LAB.md) for bounded comparison tools and evidence limits.
