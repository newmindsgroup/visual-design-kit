# Reference direction

Version-Timestamp: 2026-09-10 20:20:03 AST

Project-local instruction draft. Selection creates a recommendation, not an installation or approval.

## Inputs

Reuse the qualified brief, audience/task, medium, approved identity and existing UI-system evidence. Identify invariants, intended use, budget and unanswered decisions. A reference URL can start exploration; it does not replace these inputs or authorize copying.

## Method

Use [reference selection](../../REFERENCE-SELECTION.md) for discovery and style/motion comparison. First distinguish a reference gallery, a brand identity, a component system, an implementation skill and an agent transport. These solve different problems. Select only the relevant mode and read the candidate's actual source, rather than its directory blurb.

Inspect a small contrasting set against the same task and content. Extract relationships, such as density, hierarchy, image treatment and feedback, then author original rules. Record what stays, changes or is rejected and why. A familiar font, grid or component is not wrong merely because a preset bans it. Approved project rules and user needs govern conflicts.

If choosing a component system or DESIGN.md format, use [system adoption](../../SYSTEM-ADOPTION.md). Keep brand direction distinct from platform semantics and implementation architecture. A style recommendation need not choose a new runtime.

## Output and acceptance

Fill [reference decision](../../templates/reference-decision.md). Give the recommendation, alternatives, source/version/locator, rights and cost status, preserved baseline, adapted rules and next verification. Mark unread, inferred and gated evidence explicitly. Unknown use rights keep an asset out of production, but need not block an original provisional concept.

A selection passes only its stated decision scope. Rendered desktop/mobile, motion preference, keyboard and relevant state checks belong to implementation acceptance; a screenshot of a reference or valid token file is not that evidence. Use [quality boundaries](../../QUALITY.md), then hand approved direction to identity or UI. For a revision, preserve the [stage handoff](../design-stage-handoff/SKILL.md) baseline and delta.

## Structured constraint check

Use the [reference-decision contract](../../REFERENCE-CONTRACT.md) for a machine-checked companion to the Markdown record. Carry every baseline lock, declared derivation, source/evidence ID, operation cost and pending check into it. A valid hold preserves uncertainty. Reconcile the JSON with actual candidate files; no validator discovers undeclared replacements or proves source claims true.


## Attributed video references

Use the adopting project's authorized source register to find source candidates, then apply the existing reference decision and identity constraints. A source's visual style, extracted DESIGN.md or component example is evidence to assess, not an approved replacement for project tokens. When iterative comparison is useful, use the bounded review procedure in [video intake](../../VIDEO-INTAKE.md); retain criteria, baseline, justified changes and unresolved discrepancies. Collection membership does not grant asset rights.
