# Reusable campaign templates

Version-Timestamp: 2026-09-11T19:51:13-04:00

## Objective and inputs

Produce reusable campaign templates within the user's screen-content scope. Read the [screen workflow](../../SCREEN-CONTENT-SKILLS.md) and reuse approved upstream files, brief, source versions and constraints. The catalog dependency `display-campaigns` identifies required information, not a mandatory rerun. Missing inputs are explicit assumptions or scoped holds.

## Method

Define editable fields, locked elements, supported formats and allowable ranges. Give each field a type, source, maximum practical content and overflow behavior. Preview extreme values and missing images. Separate promotion expiry from file naming and define a valid fallback.

## Output

Editable template, field specification and example populated variants. Carry source version, candidate status, editable file location, dependencies, limitations and next owner in the [handoff](../design-stage-handoff/SKILL.md). Choose an available tool suited to the artifact; a skill does not establish authentication, paid allowance or native editing capability.

## Acceptance

Test longest copy, absent product, expired offer and unexpected dimensions without silently dropping required text. Record actual evidence and failures. Never label an unexecuted check passed. Maintain the approved baseline until the candidate is accepted.

## Constrained format adaptation

Version-Timestamp: 2026-09-11T21:22:42-04:00

Define per-format anchors, protected product bounds, copy zones, safe margins, type limits, focal crop and allowed content reordering. Reflow and reposition before reducing type size. Never stretch products, distort logos, remove required copy or crop factual details to make a template fit. If content cannot fit within readable limits, return an explicit exception for copy/layout revision rather than silently shrinking it. Automation may produce candidates only within these rules. Preview each actual generated variant using longest copy, missing imagery and localized text; inspect line balance and orphan words. Preserve source IDs and an adaptation log so repairs can be applied consistently. A rules document alone is not an implemented resizing engine.

Use the [display production detail checklist](../../templates/display-production-details.md) and preserve actual test evidence.
