# Touch device validation

Version-Timestamp: 2026-09-11T19:51:13-04:00

## Objective and inputs

Produce touch device validation within the user's screen-content scope. Read the [screen workflow](../../SCREEN-CONTENT-SKILLS.md) and reuse approved upstream files, brief, source versions and constraints. The catalog dependency `touchscreen-design` identifies required information, not a mandatory rerun. Missing inputs are explicit assumptions or scoped holds.

## Method

Use actual hardware dimensions, mounting and accessibility requirements from the deployment owner. Verify touch targets in physical context, seated/standing reach, glare and input accuracy. Browser pixels alone cannot prove accessibility. Record peripherals and assistive alternatives only when supported.

## Output

Device test matrix, observed results and unresolved installation dependencies. Carry source version, candidate status, editable file location, dependencies, limitations and next owner in the [handoff](../design-stage-handoff/SKILL.md). Choose an available tool suited to the artifact; a skill does not establish authentication, paid allowance or native editing capability.

## Acceptance

Test task completion, imprecise taps, keyboard or supported alternative input, timeout extension and clean reset; distinguish prototype from field acceptance. Record actual evidence and failures. Never label an unexecuted check passed. Maintain the approved baseline until the candidate is accepted.
