# Information design and explanation

Start from the reader's question: compare categories, see change, understand distribution, locate a relationship, follow a process or understand a part/whole. Choose the encoding that answers that question with least unnecessary interpretation. Bars need a meaningful zero baseline for length comparisons; line-axis decisions need explicit context and cannot be inherited mechanically from bar rules. Do not use 3D perspective for quantitative length/area comparisons.

Preserve units, denominator, time interval, source/date, missing values and uncertainty. Missing is not zero. An estimate is not a measured observation. Sort when it supports the question and preserve natural order when order itself carries meaning. Include direct labels and annotation for the intended takeaway. Reject decoration that suggests precision, certainty or causality not in the data.

Create a chart, source table and plain-language explanation from one canonical dataset. A table preserves numbers but may not preserve the narrative of a complex graphic. Explain relevant trends/relationships in text without overstating them. Ensure screen-reader access, table headers, keyboard controls if interactive, non-color differentiation and meaningful image alternatives. Use data-owned scales/labels in format adaptations rather than redrawing values by eye.

Handoff: question, dataset ID/version, transformations, encoding decision, rejected option, labels, explanation, uncertainty and verification. Recompute totals and trace every rendered value. The laboratory's 12/8/4 counts are explicitly synthetic and carry no real event claim.
