# Prototype

Version-Timestamp: 2026-09-12T11:33:18-04:00

Project-local instruction draft. Manual selection does not install a tool or grant permissions.

## Inputs

Task flows, risky assumptions, acceptance criteria, participant plan, intended device/context and chosen prototype tool if available. Reuse valid existing prerequisites; missing audience research follows the [shared audience rule](../../CAPABILITY-CONTRACTS.md), including its hold or specifically authorized provisional-exploration branch. Never self-authorize an exception.

## Method

Choose the lowest fidelity that can answer the question. List simulated behavior and omitted backend/device features. Build or specify the key tasks and error states with stable state IDs. Use neutral tasks without teaching the interface. Define task success, critical errors, assistance, time measurement if useful and severity rules before observation. Record participant consent and anonymized observations; do not store unnecessary personal data. Separate observed usability problems from aesthetic preferences. Recommend revisions with evidence and retest scope. If no renderer or participants are available, return the prototype/evaluation specification with those checks pending, not a fabricated study.

## Output contract

Fill [design work](../../templates/design-work.md), selecting the sections relevant to this capability. Include: Prototype state inventory, interaction specification, evaluation protocol, observations or explicit pending status, issue severity, revision and retest plan. Refer to stable IDs and paths rather than pasting full research or personas.

## Acceptance

Links/interactions are tested when built; desktop/mobile and keyboard states are checked where applicable; simulation limits and study sample are explicit. Apply [quality boundaries](../../QUALITY.md). Unsupported checks remain pending with an owner and next action. For a revision, load [stage handoff](../design-stage-handoff/SKILL.md) and compare only the authorized delta.
