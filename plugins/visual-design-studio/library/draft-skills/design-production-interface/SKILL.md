Project-local instruction draft. Manual selection does not install a tool or grant permissions.

## Inputs

Approved or provisional design state, precise output specifications, permitted assets, selected toolchain evidence and operation authorization. Reuse valid existing prerequisites; missing audience research follows the [shared audience rule](../../CAPABILITY-CONTRACTS.md), including its hold or specifically authorized provisional-exploration branch. Never self-authorize an exception.

## Software and control-route selection

Use [production routing](../../SOFTWARE-PRODUCTION.md) before choosing a renderer or native application. Select by required editable source, output fidelity and recipient workflow; use capable existing software when it meets the task better than a custom implementation. Check the route status in SOFTWARE-READINESS.md before execution; unverified routes permit bounded verification experiments within authorization, not a production-readiness claim. Load only the relevant Illustrator, Photoshop, Figma or Canva workflow linked there. Reuse verified installed skills/connectors; check actual operations, entitlement/data boundary and export/reopen evidence. Treat the [readiness snapshot](../../SOFTWARE-READINESS.md) as dated discovery, not execution proof.

## Method

Read only the selected medium row in TOOLCHAINS.md. Record tool/version, native format, export settings and dependencies as observed facts or unselected. Verify input hashes and allowed use before production. Produce editable source and exports only with an available authorized tool. Inspect exports with the actual target viewer/runtime; record settings and evidence. Keep baseline hashes, requested delta and invariants for revisions. Package output inventory and dependencies in a manifest. Do not convert file existence or successful hashing into a native reopen, device, playback or manufacturing approval.

## Output contract

Fill [design work](../../templates/design-work.md), selecting the sections relevant to this capability. Include: Production specification, local manifest, editable/output references, export parameters, toolchain state, reopen evidence and remaining acceptance checks. Refer to stable IDs and paths rather than pasting full research or personas.

## Acceptance

Paths and hashes validate; rights match intended use; outputs match measured specs; native/render/device checks are separately recorded and never inferred. Apply [quality boundaries](../../QUALITY.md). Unsupported checks remain pending with an owner and next action. For a revision, load [stage handoff](../design-stage-handoff/SKILL.md) and compare only the authorized delta.

## Shared inventory

Use the [inventory](../../SYSTEM-INVENTORY.md) for relevant entry IDs, variants, state prompts and profile choices. Complete the [item specification](../../templates/system-item.md) only for selected scope. Keep existing reference decisions, work records, baselines and handoff contracts authoritative. An inventory entry is not an implemented or tested component.

## Example and evidence discipline

Use the medium/consumption fields in the work record to distinguish live presentation from independent reading and online from offline use. Preserve the existing manifest and reopen checks. Where a builder mapping or copy/export option is documented, state whether it produces a marker, snippet, editable source or actually tested package.


## Motion and reusable asset recipes

For transcript-led visual inserts, grading, transitions, coherent animated icons or image-to-video, read only the relevant mode of [motion recipes](../../MOTION-RECIPES.md). Keep source timing, factual evidence, fixed/variable parameters, scoped asset paths, licenses and actual export/playback checks in the existing work record. These are conditional production instructions, not a tested media integration or permission for generation spend. Existing UI, software-selection and delivery contracts remain the owners of their checks.
