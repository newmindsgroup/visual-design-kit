# Source-to-export fidelity for slides and documents

Version-Timestamp: 2026-09-10 20:21:06 AST

Agent-Attribution: computer=NMG-MBP-M5.local; tool=Codex; version=codex-cli 0.149.1; timestamp=2026-09-08 22:17:00 AST

Status: authored procedure, not a new PowerPoint execution result. Use when converting an accepted HTML or other editable source to a slide/document format. Read the existing [delivery preflight](../../../DELIVERY-PREFLIGHT.md); this reference adds conversion-specific checks, not another delivery system.

1. Record source version, target format/application/version, required editability and permitted adaptations. Reuse content/slide IDs to map source sections to destination slides or pages. Index-only mapping is unsafe after reorder, split or merge. Register one-to-many mappings explicitly, including notes, hidden content, captions, citations and qualifications.
2. Define safe content regions from the actual page/slide dimensions, headings and footer requirements. Reserve their space before placing body content. Layout can advance by measured blocks or use an explicit space budget, depending on the composition. If content will not fit, change the authorized layout or propose a split; never silently remove meaning or shrink text beyond the reading requirement.
3. Compare text and semantic emphasis, not just plain strings. Preserve run-level bold/italic/link meanings where supported. Apply the [typography checks](../../design-typography/SKILL.md) to the destination font family, face, weight and glyph coverage. In PPTX, inspect relevant Latin, East Asian and complex-script font assignments when mixed scripts require them. Variable-font support is a property to test in the target application; static instances are a possible, licensed fallback, not an automatic font replacement.
4. Inspect actual shape and text bounds, transforms and groups. Footer exceptions must come from an explicit role/ID map, not a substring such as "page" or the fact that a block landed near the bottom. Check collisions as well as page bounds. Record intentional overlaps, crop behavior and medium-specific differences rather than blanket exemptions.
5. Render/reopen the exported file in the required application, or mark that check pending. Geometry cannot detect substituted glyphs, missing emphasis, bad wrapping, contrast or reading order. Render comparison cannot establish native editability or content completeness by itself. Use both evidence types, plus text/semantic comparison, for the selected requirements.

Record each difference as loss, intentional adaptation or unresolved mismatch, with source/destination ID, consequence, evidence and owner. Passing a project's own verification script is scoped evidence, never blanket permission to deliver. An internal review copy may proceed with declared limits; a required failed criterion holds the dependent production claim. Preserve failed exports and regenerate hashes only after actual corrections.

Derivation: original adaptation of the questions in Open Design's [fidelity audit](https://github.com/nexu-io/open-design/blob/bb9682a5f939cd44947300cd4c7f5195e4230250/skills/pptx-html-fidelity-audit/SKILL.md), [font discipline](https://github.com/nexu-io/open-design/blob/bb9682a5f939cd44947300cd4c7f5195e4230250/skills/pptx-html-fidelity-audit/references/font-discipline.md) and [geometry verifier](https://github.com/nexu-io/open-design/blob/bb9682a5f939cd44947300cd4c7f5195e4230250/skills/pptx-html-fidelity-audit/scripts/verify_layout.py). We do not copy or run those scripts, inherit their numeric canvas defaults, use their footer heuristics, or equate zero geometry findings with readiness. The pinned source version retains the authoring assessment; no downloaded implementation or historical check is included.
