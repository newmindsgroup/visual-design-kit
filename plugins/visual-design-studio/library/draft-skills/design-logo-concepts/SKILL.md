# Logo concept development

Version-Timestamp: 2026-09-11T19:25:03-04:00

Status: authored project-local instruction. No installation or production acceptance implied.

## Inputs and routing

Use the [identity workflow](../../IDENTITY-WORKFLOW.md) and [identity handoff record](../../templates/identity-handoff.md). Reuse accepted inputs with version and scope; dependencies are information requirements, not mandatory reruns. Existing [identity](../design-identity-system/SKILL.md) coordinates selected stages.

## Method

Use the approved/provisional name and identity direction. Freeze audience, purpose, required media, baseline locks and criteria. Reuse accepted research; do not invent category facts. Explore wordmark, symbol, monogram or combination only when suitable, not as a mandatory checklist.

Develop materially distinct ideas before cosmetic variations. Explain what each communicates and its likely limitations. Avoid presenting an unrelated stock symbol or generated raster as an original vector master. Keep references as attributed evidence, not tracing permission. Record any external elements and their rights.

Present options at comparable size with the same name, background and application content, including simple monochrome views. Beautiful mockups must not conceal weak silhouettes. Use the shared creative-direction presentation and Design Taste critique; explain meaning without inventing a story after selection. Mark all unselected candidates clearly. Obtain the appropriate concept decision before final refinement; sketches may stay provisional.

## Output and acceptance

Concept sheets with stable IDs, simple mark views, rationale, alternatives/tradeoffs, representative application and explicit selection status.

Carry file versions, approval scope and unresolved checks through [stage handoff](../design-stage-handoff/SKILL.md).
