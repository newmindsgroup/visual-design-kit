# Responsive logo systems

Version-Timestamp: 2026-09-11T19:25:03-04:00

Status: authored project-local instruction. No installation or production acceptance implied.

## Inputs and routing

Use the [identity workflow](../../IDENTITY-WORKFLOW.md) and [identity handoff record](../../templates/identity-handoff.md). Reuse accepted inputs with version and scope; dependencies are information requirements, not mandatory reruns. Existing [identity](../design-identity-system/SKILL.md) coordinates selected stages.

## Method

Derive only authorized variants from the master. For an existing brand first reuse supplied approved versions. Select primary, stacked, compact, symbol-only, monochrome, reversed, favicon/avatar and tagline/language lockups by actual need. Do not manufacture every variant or silently simplify a locked logo.

Define each variant purpose, source, permitted contexts and switching rule from observed legibility. Clear space and minimum size derive from the actual mark and tests, not invented universal proportions. Optical reversal or small-size corrections require documented approval when changing the mark. Favor art-directed switching over stretching, squashing or arbitrary cropping.

Include endorsement/co-brand placement rules when scoped, with relative prominence and permissions. Test variants on relevant light/dark/textured backgrounds. Keep app-icon platform shapes separate from the logo master. Connect motion variants to the shared motion skill and preserve the approved shape; a motion frame is not a replacement static master.

## Output and acceptance

Variant matrix with stable IDs, source master/version, allowed context, sizes/backgrounds, exact lockup text, approval and file paths.

Carry file versions, approval scope and unresolved checks through [stage handoff](../design-stage-handoff/SKILL.md).
