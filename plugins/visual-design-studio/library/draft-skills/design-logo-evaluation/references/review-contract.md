# Bounded visual review and authorized fallback

Version-Timestamp: 2026-10-02 21:00:45 AST

Use for logo critique or independent review of logo artwork. Instruction-method reviews may be text-only, but must be labeled as such and do not fulfill visual artwork review. This is an agent-followed method, not an automatic routing interceptor. This contract supplements project gates; it does not alter global provider policy, budgets, data permission or independence requirements.

## Prepare and bound

Freeze criteria, candidate IDs, accepted/rejected states, source/export versions and image hashes. Supply the actual clean artwork at target size, matched-scale original/candidate views, full-name typography/lockups and relevant context renders. Include overlays only as supplementary evidence. State which images represent native/reopened sources versus exported, generated/sketch or simulated views. If only geometry descriptions are available, hold visual judgments rather than infer quality.

Select a competent available reviewer/method for this task's images and privacy level, not a permanent preferred model. Before launching a local model verify its exact installed ID, image support, supported request format, hardware/context capacity and bounded response budget. For external review, require project-specific data authorization separately from fallback authorization. Sanitized method review does not authorize client-image uploads. Cropped, de-named, outline-only or otherwise client-derived images, measurements and identifiers remain project data unless the project's explicit sanitization/data approval covers that export. Use connector-managed/subscription authentication where authorized; no paid API, credential bridge, installation or global routing change follows from review fallback.

Set the call/phase budget, timeout and context/output limits before the call; retain existing stricter limits and stable milestone ID. Supply only the necessary images and criteria. A new endpoint, model or narrower packet does not reset exhausted attempt reservations. Create a new milestone only for a genuinely distinct authorized objective or separately required review stage, recording its scope/authority and related prior attempts. Never rename an exhausted review or present the same objective as new to reset its budget. Do not automatically retry an uncertain external call. After a failed local call, stop the loop; any deliberate repaired/narrower attempt consumes the same bounded budget and requires verified request/capacity changes. One success or failure does not establish a provider ranking for later tasks.

## Usable finding contract

A completed visual critique identifies actual reviewer/tool/model (unknown when unavailable), reviewed image IDs and coverage gaps, then returns finished criterion-level findings. Each row binds a candidate and criterion to pass/revise/not-tested, a specific image location or visible observation, its consequence and a concrete correction or reason no correction is needed. Finish with a recommendation, limitations and priority fixes. Not-tested rows preserve missing evidence and do not pass their criteria. A rejection of a candidate must identify the failed criterion rather than only assign a taste score.

Context/output exhaustion, HTTP/request errors, unclosed reasoning, partial drafting or a missing final criterion table are failed/incomplete attempts, not usable critique. Do not mine fragments for an approval, describe an unfinished call as reviewer agreement or invent a model from an alias. Record safe verbatim error/reason or status code, exact runtime ID if returned, images attempted, elapsed time, limits and whether a finished result exists. Preserve raw logs privately; redact identifiers/secrets from reusable records. Where original logs are unavailable, label the failure as reported and leave exact runtime/message unknown.

## Separate acceptance states and drawing evidence

Keep four states per exact candidate/version; do not collapse them into a review score:

| State | Evidence and boundary |
| --- | --- |
| Critique completion | Completed/failed/incomplete. Finished findings establish that the review completed, not that the artwork is acceptable. |
| Criteria evidence | Pass/revise/not-tested per criterion. Actual measured/rendered checks support individual criteria; hypotheses and untested claims remain pending. |
| User visual acceptance | Explicit accepted/rejected/pending disposition for the shown version/hash and scope, bound to the user's disposition wording or evidence pointer; praise alone is not an approval. A completed model critique does not grant this. |
| Production readiness | Required user/design approvals plus native source, export, rights and intended-use checks. No prior state alone grants readiness. |

When the user rejects reviewed options, retire those drafts from active selection while preserving the preferred/accepted source and its locked features. Do not promote them because a reviewer finished or scored them well. Renaming, re-exporting or re-hashing a rejected draft does not reset its decision. A substantively revised descendant may be compared within authorized revision scope only with its parent/rejection lineage and the specific rejection reason the new drawing addresses; its visual acceptance is pending, never inherited. Translate each valid audit finding into a testable drawing action: defect location, hypothesis, authorized parameter change, expected observable effect, retained-feature veto, and actual before/after evidence from the reopened native master or its exports, with generation/sketch views labeled separately. Apply the [controlled drawing study](../../design-logo-refinement/references/lettering-and-optics.md#controlled-contour-and-integration-study) for permitted one-group comparisons. Recommendations or revised scores without executed changes leave the drawing finding open. An executed test with no expected improvement rejects or revises the hypothesis; the original finding remains open until evidence resolves it. This is distinct from text-only instruction-method review, whose artifact is the changed instructions and whose checks cannot establish artwork readiness.

## Fallback without false completion

On failure, stop that attempt and record the remaining budget and evidence gaps. When the user has authorized other competent review methods, reassess an available method within the same privacy/capacity/attempt boundaries and record the scoped authorization, why it fits, actual fallback model/tool and result. Provider availability should not alone block permitted drafting, local native checks or a supported authorized fallback. Do not silently substitute a provider or claim the failed provider passed.

If the fallback produces a finished image-grounded critique, adjudicate its findings and rerun affected checks. For required independent review, use a reviewer process/session separate from the drafting author/session, with the actual artifacts and frozen criteria and freedom to disagree. A different model, provider or machine is not required by this method; record shared context or author-rationale exposure as a limitation and retain stricter project rules. Preserve any required independence: an author's own inspection can add evidence but cannot be relabeled independent review. Final approval/completion remains pending for unmet mandatory criteria or unsatisfied independence, while unrelated authorized draft work may continue. If no usable authorized route remains, checkpoint the exact hold and next action rather than repeatedly launching calls. Scope-level fallback approval does not rewrite global gates or authorization for later projects.

## Native geometry and rendered quality

Official sources checked 2026-10-02; locale URLs were accessible on that date, and may redirect later. When Illustrator is the requested tool, inspect both paths and painted artwork: Adobe's [viewing guidance](https://helpx.adobe.com/ie/illustrator/using/viewing-artwork.html) distinguishes Outline from Preview and describes Pixel Preview as an approximation. Record actual strokes/effects behavior when resizing; Adobe's [scaling guidance](https://helpx.adobe.com/uk/illustrator/desktop/manage-objects/reshape-transform-objects/scale-objects.html) documents Scale Strokes & Effects. Reopen and inspect chosen exports instead of relying on these settings alone. Adobe's [saving guidance](https://helpx.adobe.com/illustrator/using/saving-artwork.html) documents SVG text export options that can alter kerning/appearance. These tool facts support export comparisons, not a beauty or native-execution claim.

Use the [logo study record](../../../templates/logo-study.md) for the review receipt and keep raw images/errors in the project workspace. Geometry conformity, path validity, provider success and completed critique each establish different evidence.
