# Create brand videos in Google Vids

Version-Timestamp: 2026-10-01 21:48:22 UTC

Create a saved native Vid and an inspected review MP4. A storyboard, slide deck or externally rendered film is a preparation artifact; export alone never proves editability. Read [current product reference](references/google-vids.md) for documented features and uncertainty.

## Inputs and prerequisites
Record audience, purpose, CTA, language, target duration, ratio, destination, approved facts/assets, rights, budget and AI limits. Reuse an existing brief. Confirm master logo, photographs, palette and fonts; provisional styling stays labeled. Keep client assets and project records outside the plugin. Select dependencies from the existing project; missing brand strategy does not require rebuilding an accepted strategy.

## Workflow
1. Inventory actual assets and provenance. Use the approved logo unchanged. If no verified master exists, retain its photographed appearance and report the gap. Never invent claims, labels or packaging. Clear audio rights separately.
2. Open an isolated task tab using supported browser tools. Preserve unrelated/unsaved tabs. Confirm signed-in identity, native editing access and owner. Distinguish documented, observed, used and untested features. AI controls being visible does not prove entitlement. Inspect edition/admin availability and exact action credits before generation. If cost/credits are unknown or unapproved, use deterministic asset-based editing. Do not acquire credentials, subscriptions or credits, widen permissions or bypass denials.
3. Plan 4 to 6 concise scenes for a 20 to 30 second brief: hook, real product detail, supporting visual, brand/CTA. One message per scene, readable without audio. Favor hierarchy, safe margins, consistent crops and restrained movement.
4. Create a blank native Vid or copy an approved master. Set ratio/default styles before insertion. Build editable photo/text objects; optionally import native Slides with AI extras disabled. Confirm native objects survived import. Keep original files intact. Use photo effects and enter/exit animations sparingly; never generate/distort a logo.
5. Set scene durations, object tracks and transitions. Overlaps change total runtime. Use included/cleared audio only; trim, fade and balance under speech. Real voice cloning/personal avatars need separate consent. Preview pronunciation before generating any authorized voice. If speech is used, verify caption text/timing; Spanish voice availability does not prove Spanish automatic captions.
6. Preview all scenes and full playback. Inspect every cut, title, logo, crop, final hold and sound. Check each requested ratio separately. Save and reopen the Vid; verify editable scene/object controls and owner access.
7. Export MP4 through the visible UI, wait for processing, download and inspect actual bytes/playback. Measure dimensions, runtime and audio streams. Check first/middle/final frames and title readability. A Drive automation route uses files.download long-running operations, never files.export/exportLinks for Vids. No public scene-authoring API is verified.
8. Deliver native URL/title, MP4, asset manifest, measured runtime/dimensions, preview evidence and limitations. Keep access private; no public post/client send/broad sharing implied. Retain the deliverable tab; close completed research tabs.

## Acceptance and recovery
The evidence record has: input brief; asset authority/rights; account identity/owner; feature status; native save/reopen/editability; export filename/runtime/resolution/audio; visual/playback checks; access; blockers. Missing AI uses manual editing. Failed import uses owned images/text. Missing export readiness waits/checks visible status. Access/auth/automation blockers leave a storyboard and assets with the exact observed reason, never a claimed native completion.

Common mistakes: treating visible AI buttons as unlimited access; applying defaults without checking existing objects; counting scene lengths without transition overlap; distributing stock as raw plugin assets; equating download with editability; promising a documented feature without live verification.
